# B站线索采集 · 评论者 UID 方案（v3）

> 2026-11-01 调整后的最终方案：**采集评论者身份，不做评论区回复**，
> 后期用另一个账号 `bilibili://space/<uid>` 直达主页私信联系。

---

## 一、方案变更

| | 旧方案 | 新方案 |
|---|---|---|
| 目标 | 二次找到那条评论并回复 | 采到**发评论的人** |
| 锚点 | 视频 + 评论正文 | **评论者 UID** |
| 瓶颈 | 61%（热评漂移，滚不到） | **无**（UID 精准直达） |
| 执行 | 同号在评论区回复 | 换号私信 |

**核心变化**：不再需要"回头找那条评论"，只要拿到人的 UID。

---

## 二、三个 ID 全从系统 Intent 读

B站 手机端 UI 上看不到 BV 号，评论也不暴露 rpid，但 Activity 的 Intent 里都有：

```
视频详情页：
  bilibili://united_video/116492733518306?...&aid=116492733518306

UP 主页 / 评论者主页：
  activity://main/localauthorspace?defaultTab=video&name=XXX&mid=3546760058243958
```

| ID | 含义 | 取法 | 用途 |
|---|---|---|---|
| `aid` | 视频 ID | 详情页 Intent | `bilibili://video/av<aid>` 回看视频 |
| `mid` | UP 的 UID | UP 主页 Intent | 定位视频作者 |
| **`mid`** | **评论者 UID** | **评论者主页 Intent** | **`bilibili://space/<mid>` 直达私信** |

读取就一行：

```python
out = dev.sh('dumpsys activity activities')
mid = re.search(r'[?&]mid=(\d+)', out).group(1)
```

**为什么不用 OCR**：UP 主页的 UID 只有认证号才有「详情」按钮能展开，个人号没有——OCR 只能拿 50%。
Intent 里 **mid 是 100%**，一视同仁。

## 四、采集链路

```
搜索关键词
  → 逐个点真视频卡（点击前按 ad_marker/upuser 过滤广告）
  → 详情页：关全屏广告 → 读标题/UP → Intent 取 aid
  → UP 主页：Intent 取 up_uid
  → 点「评论」tab（认 tab_title，不能只认文字）
  → 读一屏评论 → 逐条点昵称 → 主页 Intent 取 commenter_uid → BACK
  → 滚下一屏，重复
```

**关键顺序**：必须「读一屏 → 点一屏 → 再滚」，不能"先滚着读完再统一点"。
因为读完时页面停在最后一屏，前面屏的作者已经不在屏幕上，点不到（实测覆盖率会掉到 0）。

## 五、六个坑（都已修）

| # | 坑 | 后果 | 修法 |
|---|---|---|---|
| 1 | `adb shell input text` 不支持中文 | 搜中文标题搜空 | 用 u2 `set_text` |
| 2 | 作者识别抓到状态栏 | `02:15`、`54%` 被当评论人 | `BAD_AUTHOR` 正则 |
| 3 | 搜索结果混广告卡 | 误入 `AdIMaxActivity` | 点击前按 `ad_marker`/`upuser` 判断 |
| 4 | 详情页全屏广告 | dump 到广告树 | 找 `content-desc="关闭"` |
| 5 | 「评论」tab 点不中 | 在简介区解析评论，采到「AI开源先锋计划」这类标签 | 认 `tab_title` id + 确认出现「热门评论」 |
| 6 | 读评论块没约束 | 标签/UP 名被当评论 | 块内必须有点赞/回复节点 |

## 六、⚠️ 必须提醒：手机端没有私信入口

之前实测（2026-10-31，B站 9.16.1 Android）：

- 用户主页**没有「私信」入口**（关注/未关注都试过，菜单只有「加入特别关注 / 设置分组 / 取消关注」）
- 消息中心没有发起私信的入口
- 通讯录只有空的关注/粉丝列表

**所以"用其他账号私信"这一步，在手机 App 内可能走不通。**

可选路径：
1. 换用**网页版**（PC 端 B站 有私信功能）
2. 或用手机浏览器打开 `space.bilibili.com/<uid>` 私信
3. 或改用**评论区回复**（但那就回到"需要找到那条评论"的老问题）

建议先确认这条通路，再决定采集量。
