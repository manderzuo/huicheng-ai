## 四、踩到的坑与修复

### 坑 1：每单都退到桌面（本次新发现）

**现象**：每处理一条私信，App 就退回桌面再重新启动一次。

**原因**：`open_dm()` 里为了"保证状态干净"，每单都执行 `am force-stop tv.danmaku.bili`。

**代价**：每单多 3~5 秒冷启动，110 单多花 8 分钟，而且视觉上很难看。

**修复**：去掉 `force-stop`，直接用 DeepLink 在 App 内跳转。
只有当前完全不在 B站 时才拉起一次。改完后连续跑 78 单，再没退过桌面。

### 坑 2：评论人就是 UP 本人

**现象**（主人指出）：UP 在自己评论区发言，也被当成潜在客户采进来。

**修复**（两处防护）：
1. 采集时：拿到 `cuid` 后判断 `cuid == up_uid` 直接丢弃
2. 入库时：`push_batch` 再挡一次

本次 113 条中该情况为 **0 条**（解析评论时本来就会跳过带 `UP` 标记的块），防护已就位。

### 坑 3：中文关键词搜不出来

`adb shell input text` 不支持中文，「手机挖矿」会静默变成空串。
改用 u2 的 `set_text`（走剪贴板）。

### 坑 4：输出被缓冲，看不到进度

Python stdout 缓冲导致后台任务长时间无输出。
改用 `python -u` 无缓冲，并把日志改为「边采边写中转站」，进度可直接查库。

### 坑 5：「评论」tab 点不中

简介区、底部栏都有「评论」二字，用 `find_text` 容易点偏，导致在简介区解析评论，
采到「AI开源先锋计划」这种标签。
改为认 `resource-id` 后缀为 `tab_title` 且文字为「评论」的那个，并确认出现「热门评论」再继续。

## 五、⚠️ 必须知道的限制

### 私信只能发 1 条

私信会话页明确写着：

> **对方主动回复或关注你前，最多发送 1 条消息**

所以每个线索**只有一次机会**，文案必须一次到位，不能试错。

### 文案目前是统一模板

本次草稿都是：

```
你好呀，看到你在评论区提到「<关键词>」相关的问题，我这边整理了一份入门资料，需要的话回我一下～
```

按关键词替换，**没有按人个性化**。如果要提高回复率，建议后续改成引用对方评论原文。
（`run_dm_task.py` 已支持 `{昵称}` / `{评论}` 占位符，只是本次入库的模板没写。）
