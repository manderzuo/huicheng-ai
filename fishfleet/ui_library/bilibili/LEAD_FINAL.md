## 二、最关键的一次排查：问题根本不在 B站

**现象**：从 00:00 起，搜索页、用户主页、视频详情**全部加载不出来**——
「加载失败」「正在加载数据…」、详情页一整屏灰色骨架屏。

**我一开始的误判**：以为 B站 接口限流（因为 ping 通、首页还能看）。
这个判断**是错的**——首页看的是本地缓存。

**真正原因**：设备上跑着一个 VPN：

```
VPN CONNECTED
TransportInfo: <VpnTransportInfo{type=1, sessionId=Kitsunebi}>
InterfaceName: tun0
Routes: [ 0.0.0.0/0 -> 0.0.0.0 tun0 ]
```

包名 `fun.kitsunebi.kitsunebi4android`（Kitsunebi），它把 B站 所有域名解析到了**虚拟地址**：

| 域名 | VPN 开着 | 停掉 VPN 后 |
|---|---|---|
| www.bilibili.com | `172.255.8.211` | **`116.163.15.200`** |
| search.bilibili.com | `172.255.8.214` | 真实 CDN |
| api.bilibili.com | `172.255.8.237` | 真实 CDN |
| **HTTP 状态** | **`000`（连接被断）** | **`200` ✅** |

停掉 Kitsunebi 后，B站 **立刻恢复**，采集一次就跑通。

**教训**：诊断"连不上"时，先查 DNS 和路由（`dumpsys connectivity` / `ip route`），
不要被"ping 通""首页正常"这种表象骗过去。

## 四、三个关键设计

### 1. 用 DeepLink 搜索，绕开输入法

B站 搜索框会自动填充搜索建议，`set_text` 写完立刻被覆盖：

```
输入「挖矿木马」→ 变成「电脑中病毒cpu占用高」
输入「矿池」    → 变成「darkanddarker挖矿」
```

零延迟回车都拦不住。改用 `bilibili://search?keyword=<urlencode>`，**100% 可靠**。

### 2. 锚点越硬越好

| 锚点 | 可靠性 |
|---|---|
| 视频标题 | 低（会被截断、被简介小标题抢占） |
| UP 名 | 中（重名） |
| **`aid` / `mid`** | **100%**（从 `dumpsys` Intent 读，数值型） |

评论者 UID 靠点昵称进主页、从 Intent 取 `mid`，本轮 173/200 拿到（86.5%）。

### 3. 相关性过滤必须双向

```python
RELEVANT = r'(显卡|挖矿|矿卡|矿机|矿场|加密货币|比特币|以太坊|区块链|币圈|'
           r'虚拟货币|算力|矿池|BTC|ETH|挖币|炒币|数字币|矿潮|矿渣|'
           r'40HX|30HX|90HX|P104|P106|P620|V100|RX580|5700XT|显存|魔改)'
RELEVANT_EXCLUDE = r'(电动矿卡|露天矿|矿用卡车|自卸|矿山车|柴油|矿洞|矿井|矿难|瓦斯|煤老板|矿工被困|井下)'
```

**光有正向词不够**：「矿卡」在矿山语境也常用，**必须有排除词**，
否则「电动矿卡」「露天矿」这些矿山卡车内容会混进来。

实测 8/8 判断正确。
