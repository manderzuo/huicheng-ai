# B站截流 · 持续测试问题清单

> 2026-11-01 晚 ~ 2026-11-02 凌晨
> 记录持续测试中发现的每个问题、根因与修复状态。

---

## 一、已修复（8 个）

### BUG 1：搜索词被 B站 搜索建议覆盖 ★最隐蔽

**现象**：脚本"搜到"的结果和关键词完全无关——输入「挖矿木马」搜出「CPU占用100%」，
输入「矿池」搜出「darkanddarker挖矿」。

**根因**：点击搜索框时 B站 会**自动填充一个搜索建议词**，`set_text` 写完立刻被覆盖。
加清空、加零延迟回车都拦不住。整轮采集因此产出 0 条。

**修复**：改用 **DeepLink 搜索**：

```
bilibili://search?keyword=<urlencode>
```

实测三个关键词全部正确带入，100% 可靠，彻底绕开输入法。

---

### BUG 2：缩进错位导致核心逻辑变死代码 ★最严重

**现象**：每个视频都进了详情页（打印"已关广告"和 UP 名），但什么都不做就滑到下一个，
日志里连"跳过原因"都不打印，整轮 0 产出。

**根因**：加相关性校验时缩进写错：

```python
        if not relevant_title(title):     # 8 空格（循环体级）
            print(...)
            continue
            # ↓ 下面全部变成死代码，永远不执行 ↓
            if not up_name:               # 12 空格
            uid = get_uid(...)
```

`if` 的 `continue` 把后面整段逻辑挡成了死代码。

**修复**：`if` 块缩进改为 12 空格，与后续逻辑同级。

---

### BUG 3：搜索页「加载失败」被当成"该词没结果"

**现象**：搜索页显示「加载失败，请稍后再试」，脚本认定该关键词已翻完，直接切下一个词。

**修复**：加 `recover_load_failure()`，检测到「加载失败」就点「再试一次」，最多 3 次；
彻底失败则跳过该词并明确打印原因。

---

### BUG 4：搜索结果还没渲染就判"翻完"

**现象**：`search_cards` 返回 0，被误判成"该关键词结果已翻完"。

**修复**：
1. `search_cards` 加 2 次内部重试（间隔 2 秒）
2. `do_search` 改成**轮询等待**：最多 12 轮 × 2.5 秒，等到出现卡片或「加载失败」才返回

---

### BUG 5：标题取错，拿到简介里的小标题

**现象**：详情页 `read_header` 读到的标题是 `'病毒'` 两个字，导致相关性校验误杀，
把「AI 使我电脑挖矿」这种明显相关的视频判成"无关"。

**根因**：详情页有多个 `id=title`（视频标题 + 简介内小标题 + 相关推荐），
`read_header` 按 y 坐标筛，抓到的是简介内的小标题。

**修复**：标题**优先用搜索卡片**的（`card['title'] or head['title']`），卡片标题最可靠。

---

### BUG 6：评论少的视频被误判"没进评论区"

**现象**：`open_comment_tab` 返回 False，整个视频白跑。

**根因**：它要求点完必须看到「热门评论」或「按热度」。
但评论少的视频不显示排序栏，就被判成失败。

**修复**：改成认 `comment_container` 这个容器 id，或用「回复/点赞」这类操作兜底。

---

### BUG 7：关键词歧义采回大量无关线索 ★影响最大

**现象**：搜「矿难」采回一堆**煤矿事故**（山西82人矿难、瓦斯爆炸、智利矿工），
这些观众根本不是显卡挖矿客户。

**实测**：430 条里 **317 条是废数据（74%）**。

**修复**：
1. 加 `relevant_title()` 相关性校验，标题必须含
   `显卡|挖矿|矿卡|矿机|矿场|加密货币|比特币|以太坊|区块链|币圈|虚拟货币|算力|矿池|BTC|ETH|挖币|炒币|数字币|矿潮`
2. 注意**不能放「矿工」**——它在煤矿语境更常见，会误放煤矿视频进来
3. 已入库的 317 条无关线索标成 `skipped`

---

### BUG 8：私信主页加载失败被记成账号失败

**现象**：5 条私信全报「没进入私信会话页」，但其实是主页 WebView 没加载出来。

**修复**：
1. `open_dm` 检测「加载出错/加载失败」，点「再试一次」重试
2. 这类失败退回 `pending`，不污染 `failed` 统计

## 二、FishFleet 内嵌版同步修复

`fishfleet/web/bilibili_lead.py`（界面里跑的那份）是用 MCP 读树 + adb 点击写的，
和独立脚本是两套代码，同样的坑它也有，已同步修好：

| 问题 | 独立脚本 | FishFleet 版 |
|---|---|---|
| 搜索被建议词覆盖 | ✅ DeepLink | ✅ DeepLink |
| 搜索页「加载失败」 | ✅ 重试 | ✅ `recover_load_failure()` |

| 无相关性过滤 | ✅ RELEVANT | ✅ RELEVANT |

**教训**：两套实现必须同步修，否则界面上跑的还是旧 bug。

## 三、私信文案个性化

原模板是统一死文本：

```
你好呀，看到你在评论区提到「手机挖矿」相关的问题，我这边整理了一份入门资料…
```

**两个问题**：
1. 入库时 `% keyword` 就把占位符替换掉了，存进去是死字符串，运行时没有个性化空间
2. 没有引用对方说的话，回复率低

**修复**：
1. 入库保留占位符 `{keyword}` / `{评论}` / `{昵称}`
2. 运行到 `personalize()` 时才替换
3. 新增 `clean_quote()`：清掉评论里的换行、`[笑哭]` 表情码、`@某人`、`//xxx//`、链接
4. 清洗后没实质内容时，自动去掉引用段，保证句子通顺

效果：

```
有内容：…相关视频下留言「比刷若子视频好」，我这边整理…
无内容：…相关视频下，我这边整理…
```

### 接口限流（外部因素）

**现象**：搜索页长期停在「正在加载数据…」或「加载失败」，
主页 WebView 同样加载不出来。B站 首页（自绘 UI）正常，说明不是网络问题。

**影响**：采集和私信都做不了，只能等。

**处理**：等 15 分钟以上再试；连续失败说明还在限流。

## 四、经验总结

1. **锚点越硬越好**：标题 → UP名 → `aid`/`mid`（Intent 里读，100% 准）
2. **B站 搜索建议会抢输入框**，中文输入必须走 DeepLink
3. **关键词选择决定数据质量**：「矿难」「算力」这类歧义词要慎用
4. **详情页有多个同 id 元素**，取值要交叉验证
5. **接口限流时不要硬采**，等待比蛮干有效
