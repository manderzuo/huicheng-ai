## 二、关键突破：从系统 Intent 里读 ID

这是本次最有价值的发现。B站 手机端的 UI 上**看不到 BV 号，评论也没有 rpid**，
但 Activity 的 Intent data 里什么都有：

```
视频详情页：
  bilibili://united_video/116492733518306?...&aid=116492733518306&bvid=

UP 主页：
  activity://main/localauthorspace?defaultTab=video&name=<URL编码的昵称>
  &mid=3546760058243958&from=3&avid=116492733518306
```

- **`aid`** = 视频 ID → `bilibili://video/av<aid>` 可直达
- **`mid`** = UP 的 UID → `bilibili://space/<uid>` 可直达

读取方式一行命令：

```python
out = dev.sh('dumpsys activity activities')
aid = re.search(r'[?&]aid=(\d+)', out).group(1)
mid = re.search(r'[?&]mid=(\d+)', out).group(1)
```

**为什么这比 OCR 强**：UP 主页的 UID 只有「认证号」才有「详情」按钮能展开看到，
个人号根本没有那个按钮——用截图 OCR 只能拿到 50%。
而从 Intent 读 **mid 是 100%**，个人号认证号一视同仁。

实测 100 条采集：**aid 100%、uid 100%**。

## 三、三轮方案对比

| 方案 | 视频定位 | 评论定位 | 说明 |
|---|---|---|---|
| 搜标题 + 标题模糊匹配 | ~70% | 30% | 标题会被截断成「合集 · XXX」 |
| 搜标题 + **UP 名**匹配 | ~85% | 40% | 结果卡自带 `upuser`，比标题可靠 |
| **aid DeepLink** | **100%** | **61%** | 当前方案 |

每轮的提升都来自"换一个更稳的锚点"：
标题 → UP 名 → 视频 ID。

## 四、验证失败分析（39 条）

| 类型 | 数量 | 例子 |
|---|---|---|
| 作者为空 / 广告文案 / 超短 / 刷屏 | **13** | `¥39.9起 轻点两下查看详情`、`token来！` |
| 真实评论但滚不到 | 26 | `已三连，求工具包老师` |

**13 条噪声是采集端的问题**，不该采进来。剔除后命中率是 **70%**。

剩下 26 条滚不到的原因：
- 视频评论太多（几千上万条），热门排序下滚 15 次也未必撞上
- 「已三连求资料」这类评论**大量重复**，即使滚到也可能是别人的

## 五、五个坑（都已修）

### 坑 1：`adb shell input text` 不支持中文
采集用 `aigc`（ASCII）正常；搜索中文标题时静默失效，等于搜了个空串。
→ 改用 u2 的 `set_text`（走剪贴板）。

### 坑 2：作者识别抓到状态栏
评论区按「时间」节点切块，块里第一个 `text==desc` 的短文本当作者，
结果把 `02:15`（时钟）、`54%`（电量）当成了评论人。
→ `BAD_AUTHOR` 正则排除时间/电量/计数。

### 坑 3：搜索结果混着广告卡
点进去是 `AdIMaxActivity` / `AdWebActivity`，白跑。
**判据**：真视频卡有 `upuser` + `duration`；广告卡有 `ad_marker` / `ad_tint_frame` / `adDownloadText`，**没有 `upuser`**。
→ 点击前就筛掉，改完后全程没再误入广告页。

### 坑 4：详情页会弹全屏广告
进视频后被「学堂在线」这类广告盖住，dump 到的是广告树。
→ 找 `content-desc="关闭"` 点掉。

### 坑 5：不能用「回顶部」预滑动
曾为了"从顶部开始找"先向下滑 3 次，结果把页面拉回视频区，
后面 15 次滑动全在画面上白跑。进视频点「评论」后本来就在顶部。

## 六、OCR 的定位

装了 `rapidocr_onnxruntime`，但 **onnxruntime 在本机 Python 3.12 上一导入就崩**（0xC0000005）。

改用 **Windows 系统自带 `Windows.Media.Ocr`**（零依赖，可用语言 `zh-Hans-CN`），
封装在 `ocr_win.py`。实测能准确读出 UID（`1848018`）。

但自从发现 Intent 方案后，OCR 降级为**备用通道**：
主用 Intent（100%），Intent 取不到时 OCR 兜底。

## 七、建议

### 推荐：同场执行
采集到线索**立即**在原页面点「回复」发送，不做二次检索。
- 成功率接近 100%
- 代价：单机串行，慢
- 这是当前唯一"稳"的做法

### 若坚持跨时段
当前 61%~70%，可再优化：
1. **采集端过滤噪声**（广告文案、超短、刷屏）—— 能直接回收 13 条
2. 采集时记录评论在第几屏 → 验证直接滑到该位置
3. 跳过评论数 > 5000 的视频（漂移最严重）
4. 评论排序切「按时间」，且采集/验证都用同一排序
