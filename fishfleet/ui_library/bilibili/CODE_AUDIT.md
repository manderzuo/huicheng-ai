## 二、安全性：通过 ✅

**唯一会真正发消息的函数 `dm_bili.send()`**：

审核前：
```python
def send(dev):
    """点发送。调用前务必已获得人工确认。"""
    dev.sh(f'input tap ...')    # 直接点
```

**问题**：只有注释警告，代码层面无保护，误调用就会发出去。

审核后：
```python
def send(dev, confirm=False):
    if not confirm:
        raise DMError('拒绝发送：必须显式传 confirm=True（这是人工确认位）')
```

**验证**：
```
$ dm_bili.send(None)
→ 拒绝发送：必须显式传 confirm=True（这是人工确认位）
```

**全仓库调用点**：只有注释和审计脚本自身，**没有任何实际调用**。

`sent_at > 0` 计数始终为 **0**。

## 五、值得肯定的设计

1. **三段硬锚点**：`aid` / `up_uid` / `commenter_uid` 全部从 `dumpsys` 的 Intent 读，不依赖 UI 文本
2. **边采边入库**：每采完一个视频就推一次，中途崩了不丢数据
3. **UP 去重**：同一 UP 最多采 3 条，避免一个视频刷满
4. **UP 本人过滤**：双重保险（采集时 + 入库时）
5. **相关性双向过滤**：正向词 + 排除词，避免「矿卡」混进矿山卡车
6. **发送零路径**：`run_dm_task` 里根本没有点发送键的代码

---

## 六、建议（按优先级）

1. **P2-7 `main` 加异常保护**：一条视频出错不该中断整轮
2. **P2-11 `dm_text` 空值兜底**：空模板应该用默认文案而不是清空输入框
3. **P2-12 异常后清理**：`except` 里加 BACK 回首页
4. **P2-9 加载失败终态检查**：3 次重试后如果还有错，明确抛错
5. **P2-10 私信图标改自适应**：从 UI 树找右上角图标，而不是硬编码坐标
