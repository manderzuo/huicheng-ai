## 三、三类「没采到」的原因

### A. 需要账号数据（我无法自造）

| 页面 | 缺什么 |
|---|---|
| 我的收藏（有内容态） | 账号收藏数为 0 |
| 消息分类列表（有内容态） | 三个分类全空 |
| 真人私信会话 | 从未有真人私信 |

**这些不是技术障碍，是数据障碍**。要么主人在手机上真实操作产生数据，要么明确授权我操作（收藏一条/发一条私信——后者是外发，我不会主动做）。

### B. 需要横屏（实测连横屏都转不过去）

| 页面 | 说明 |
|---|---|
| 视频详情·横屏全屏 | 进入即横屏 + 大会员浮层，BACK 被吃 |
| 「更多操作」菜单 | 只在横屏工具栏渲染 |

**实测结果**：在竖屏详情页 `set_orientation landscape` **无效**——App 在该页锁定竖屏，转屏后 dump 仍是 1080×1920，工具栏依旧不出现。所以「更多操作」菜单在当前手段下**采不到**。唯一线索是第一次（第 1 轮）误入横屏全屏时，dump 里出现过 `toolbar_action_overflow`（label「更多操作」），说明它确实存在，只是拿不到稳定入口。

### C. 技术不可读

| 页面 | 原因 |
|---|---|
| UP 主个人主页 | 纯 WebView，且 `/proc/net/unix` 无 `webview_devtools`（release 未开调试），CDP 走不通 |
| 预测广场 / 每日有料 | MWebActivity，内部节点全不可读 |

## 四、采集方法（可复现）

| 场景 | 做法 |
|---|---|
| 列设备 | `mobile_list_available_devices`（20 台 Galaxy S10，手机4 = `192.168.31.248:5555`） |
| 认页 | 先 dump，按 `LOGIC.md` 的锚点表匹配，命中即停 |
| 记录 | 每页一个 JSON，写进 `ui_library/bilibili/pages/` |
| 进竖屏详情 | `adb shell am start -a android.intent.action.VIEW -d 'bilibili://video/<BV号>'` |
| 回首页 | 循环 BACK + 每步校验 Activity，别用固定次数 |
| 校验 | 每次改动跑一致性脚本（页面数 / 索引数 / 模块数 / JSON 合法性） |

## 五、如果要继续，优先级建议

1. **收藏列表结构**（需数据）——价值高，一条收藏即可解锁
2. **「更多操作」菜单**（需横屏）——里面是稍后再看/下载/不感兴趣/举报，属于自动化常用项
3. 综艺频道（同构，低价值）
