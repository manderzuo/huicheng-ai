## 全链路（视频路径）

```
首页底栏「发布」
  → 底部弹窗（从相册选择 / 相机 / 写文字 / 取消）        [IndexActivityV2 内]
  → 相册选择页 CapaAlbumActivity
  → 视频预处理页（选择 / 一键成片 / 下一步）
  → 视频编辑页 VideoEditActivityV3（特效/文字/标记/贴纸/截取/更多/下一步）
  → 发布笔记页 CapaPostNotePlatformActivity
       标题 EditText → 正文 EditText → 话题推荐
       → 话题/用户/投票 → 标记地点 + 附近地点
       → 底部：存草稿 / 发布笔记
```

## 发布入口弹窗

- 前台仍是 `com.xingin.xhs.index.v2.IndexActivityV2`，弹窗叠加在首页之上。
- 结构：`从相册选择` TextView（1080×158）／`相机` + `拍摄与直播`（LinearLayout）／
  `写文字` TextView／`取消` TextView。
- 注意：`写文字` 是纯文字笔记入口，不走相册；视频发布必须走 `从相册选择`。

## 相册选择页（CapaAlbumActivity）

- 顶部：`关闭` ImageView(144×105)、`全部` + 下拉箭头、`草稿箱`。
- 分类 Tab（ActionBar$Tab + Button）：`全部`(selected)、`视频`、`照片`、`实况图`、`全屏图`。
- 素材网格：RecyclerView，每格 FrameLayout(354×354) + ImageView +
  右上选择圆点 FrameLayout(131×131) + 视频时长 TextView（形如 `0:05`）。
- **素材是用户相册隐私，不得写入日志或资料库。**

## 视频预处理页

- 无独立 Activity 名（仍属相册流程），锚点：`一键成片`、`下一步`。
- 控件：`返回` ImageButton、播放按钮 ImageButton(189×189)、
  VideoSeekBar 时间轴（`00:00` … `00:05`）、`选择` TextView、
  `一键成片` TextView、`下一步` TextView（label=`下一步`）。

## 视频编辑页（VideoEditActivityV3）

- 控件：`返回` ImageButton、`选择音乐`（label + TextView）、VideoSeekBar、
  底部工具条 FrameLayout×6：`特效`、`文字`、`标记`、`贴纸`、`截取`、`更多`、
  以及 `下一步` TextView（828,1668，210×105）。
- ⚠️ 此页 `下一步` 是 **text 精确值、无 label**；预处理页的 `下一步` 是 **label**。
  模板里两种都写了，避免漏判。
- 自动化发布**不应**触碰特效/文字/贴纸，直接下一步。

### 关键结论

1. **`发布笔记` 空内容时不带 `disabled`**（与抖音/评论回复框不同）。
   → 不能靠 disabled 判断能否发布，必须在点击前自行校验标题/正文非空。
2. **标题和正文没有可用 id**，只能按 y 坐标排序区分：第 1 个是标题、第 2 个是正文。
3. 话题直接以 `#话题` 内联写进正文；发布页**没有独立话题输入框**。
4. 话题推荐列表（`#小红书土猫大赏` 等）是根据内容/相册动态生成的，**不能作为锚点**。
5. 附近地点列表同样是动态的，未点击。

## 端到端实跑结果（2026-10-31 22:39–22:44，真实发布 1 条并已删除）

素材：桌面 `测试1.mp4`（1,946,238 字节）→ `MediaPusher.ensure_video` →
`content://media/external/video/media/95`。
标题 `测试发布请忽略`，正文 `这是一次自动化测试，发布后立即删除。`

### 分享 intent 直达发布页（重要）

```
adb shell am start -a android.intent.action.SEND -t video/mp4 \
  --eu android.intent.extra.STREAM content://media/external/video/media/95 \
  -p com.xingin.xhs --grant-read-uri-permission
```

执行后 `mCurrentFocus` 直接是 `CapaPostNotePlatformActivity`——
**跳过了相册选择、视频预处理、视频编辑三页**。
所以「逐级点下一步」只是防御性逻辑，正常路径一次到位。

### 填表实测

- 点标题框后右侧出现 `删除` ImageView 与一个数字：标题填 7 字时显示 `13`，
  即**剩余可输入字数**（上限 20 成立）。正文框无计数。
- 标题、正文回读都干净，无 hint 前缀污染（与搜索框的 `搜索, xxx` 不同）。
- 正文填入后，下方话题推荐列表内容随之变化（猫相关 → 防鸟撞/捕风追影），
  再次印证**推荐列表是动态的，不能当锚点**。
- 空内容与填满内容时，`发布笔记` Button **都不带 disabled**。

### 发布成功后的界面（关键数据）

点一次 `发布笔记` 后：

1. 前台立刻回到 `com.xingin.xhs.index.v2.IndexActivityV2`；
2. 顶栏 **自动切到 `关注`**（并非原来的发现/同城）；
3. feed 顶部出现本人新笔记卡片，作者 `老学究`、时间 `刚刚`、`赞`；
4. **没有出现可稳定抓取的「发布成功」提示条**（可能一闪而过）；
5. 「我」主页出现作品卡，label 精确为
   `视频,测试发布请忽略,来自老学究,0赞，0阅读`
   —— 这是最可靠的核验依据；
6. ⚠️ **「公开 N」计数不随发布刷新**：发布前读到 `公开 10`，发布后仍是 `公开 10`，
   删除后依旧是 `公开 10`。**绝不能用它判断发布成功或失败**。

### 笔记详情页（自己发的）

- `noteContentLayout` FrameLayout 的 label = 标题 + 换行 + 正文；
- `noteContentText` TextView 的 text 同样完整包含标题与正文；
- 作者是 `Button label="作者老学究"`；
- 顶部 `返回`、`更多` 两个 ImageView；底部 `说点什么...`/点赞/收藏0/评论0；
- 视频页有 `全屏观看`、`VideoSeekBar`、`已播放到x分y秒，共0分5秒`；
- 正文下方还有 `可能含AI生成内容` 提示（该素材触发，非所有笔记都有）。

### 删除路径（实测，需两次确认）

```
笔记详情 → 右上 `更多` → 「分享至」面板
  → 第三行横向列表**左滑到底** → `删除`
  → 弹窗选 `删除笔记`（另有 删除并重新编辑 / 仅自己可见 / 取消）
  → 二次确认 `确认永久删除作品？` → `确认删除`
```

- 「分享至」面板第一行是好友/渠道，第二行是私信好友/QQ，第三行才是
  `编辑`、`置顶笔记`、`薯条推广`、`复制链接`、`小窗播放`、`播放设置`、
  `权限设置`、`合作码`、**`删除`**、`使用原声`——**删除在很靠后的位置，必须横向滑动**。
- 只点「更多」或长按卡片都进不了删除菜单；长按卡片行为等同点击卡片（进详情）。
- 删除后主页卡片消失，恢复为原有的 `视频,猫的耐心,...`。

## 补充测试（2026-10-31 22:47–23:00，图片／字数／草稿／相机／多图）

### 图片发布：单张 SEND 同样直达发布页

```
adb shell am start -a android.intent.action.SEND -t image/jpeg \
  --eu android.intent.extra.STREAM content://media/external/images/media/97 \
  -p com.xingin.xhs --grant-read-uri-permission
```
→ 直达 `CapaPostNotePlatformActivity`，与视频一致。**图片同样可以自动化发布。**

图片推送流程：`MediaPusher.push()` + `wait_for_media()`（没有 `ensure_video` 那样的图片专用封装，
但 `wait_for_media` 会同时查 video 和 images 两张表，实测返回 `images/media/97`）。
注意：推送后必须触发 `MEDIA_SCANNER_SCAN_FILE` 广播，否则媒体库可能查不到。

### 图文发布页 vs 视频发布页（三处差异）

| 项 | 视频页 | 图文页 |
|---|---|---|
| 顶部预览 | 单个视频 + `选封面` | **横向图片列表**（204×124/格）+ 加图按钮 |
| 标题框 y | 752 | **536** |
| 正文框 y | 883 | **667** |
| 额外行 | 无 | **`公开可见`／`添加组件`／`高级选项`** |

两页的标题/正文仍是「第 1 个 EditText 是标题、第 2 个是正文」的规则，按 y 排序的取法通用。

### 标题上限：20 字，静默硬截断

输入 23 字 `这是一条超过二十个字上限的标题用于测试截断` →
回读 `这是一条超过二十个字上限的标题用于测试截`（**恰好 20 字**），旁边计数显示 `0`。
所以标题计数是**剩余可输入字数**，且**超限不会报错，直接吞掉多余字符**。
→ 代码里必须自己拦截，不能让用户以为发全了。

### 正文上限：不是 1000，实测 6100 字仍未截断

逐次追加 1000 字：2100 → 3100 → 4100 → 5100 → **6100 全部写入，未截断**。
旧版「正文 1000 字上限」在当前 `v.9.4.0.8a83615` 已不成立。
→ 代码取 6000 作为实测安全值（`BODY_LIMIT`），避免误拒正常长文；真实上限仍未测到。

### 草稿箱

- 发布页点 `存草稿` → 弹 **`确认保存笔记至草稿箱吗?`**（取消／确定）。
- 确定后回到个人主页，`本地草稿` 卡片由 `有2篇笔记待发布` 变为 **`有3篇笔记待发布`**。
- 草稿**不计入 `公开 N`**（仍显示 10）。
- 草稿箱入口：个人页 `本地草稿` → `本地草稿` 页（提示「草稿在应用卸载后会被删除，请及时发布」），
  双列卡片，卡片右上角 ImageView 点开是 **`删除草稿`** → `确定删除该草稿吗？` → 确定。
- 删除后回到 `有2篇`。实测草稿箱里另一张是 10-28、10-27 的旧草稿。

### 相机入口

发布弹窗点 `相机` → 直接进 `com.xingin.capa.lib.newcapa.camerahub.CameraHubActivity`，
**没有弹任何权限请求**（该机小红书已持有相机权限）。
页面：`关闭`、`选择音乐`、右侧 `翻转／滤镜／美颜／闪光灯`、底部 `拍摄` / `直播` 两个 Tab，
另有 `视频` / `照片` 切换与美颜预设「自然 原生自然自然肤质」。
→ 换机或权限被拒时会不同，自动化前应先检查权限，不能假定一定能进。

### 多图：SEND_MULTIPLE 只到相册页

```
-a android.intent.action.SEND_MULTIPLE -t image/* (+多个 EXTRA_STREAM)
```
→ 只打开 `CapaAlbumActivity`，**素材一个都没预选**。所以多图无法靠 intent 直达，
必须走 UI 手选。当前技能**不支持多图**，只支持单素材。

### 相册多选交互（重要，容易踩错）

| 操作 | 结果 |
|---|---|
| 点素材**缩略图** | 立即选中并**直接进入下一步**（单选即跳转），看不到多选态 |
| 点素材**右上角圆点**（131×131） | 进入多选态，圆点显示序号 `1`、`2`…，可继续点 |
| 多选后底部 | `下一步(N)`（text 带数量，如 `下一步(2)`），label 仍是 `下一步` |
| 已选预览条 | 横向缩略图列表，每张带 `删除` ImageView |
| 底部分类 | `全部`／`视频`／`照片`／`实况图`／`全屏图`；顶部还有 `全部`／`草稿箱` |

→ 自动化若想发单素材，**点缩略图最快**；若要发多图，必须点圆点并按 `下一步(N)` 校验数量。
