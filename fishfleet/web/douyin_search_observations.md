## 视频筛选（视频标签，截图时可见范围）
- 排序依据：综合排序、最新发布、最多点赞、最多评论、最多收藏。
- 发布时间：不限、一天内、一周内、半年内。
- 视频时长：不限、1分钟以下、1-5分钟、5分钟以上。
- 搜索范围：不限、关注的人、最近看过、还未看过。
- 位置距离：不限、同城。
- 选项为无资源 ID 的 View，label 形如“已选中，综合排序，按钮”或“未选中，一周内，按钮”；多个“不限”需按组标题及区域归属，不可全局唯一匹配。
- 操作：选择最新发布、一周内，点击“查看结果”，结果页显示一条 6 天前的视频。返回后重新打开筛选，树中再次显示两项已选中；这验证了本次选择状态保留，但不证明服务端筛选语义完整，其他选项未逐个点击验证。

## 用户分类：关键限制（影响截流可行性）
- 切到“用户”标签后，分类栏会横向滚动（商品移出、音乐出现），分类顺序随滚动变化，仍需按文本+selected 判断。
- **列表页 UI 树只暴露“关注按钮”（无资源 ID，label“关注按钮”），昵称、粉丝指数、简介、公司名、认证标识全都没有出现在树里**；截图确认这些文字确实显示在屏幕上。即该列表的主要信息对无障碍/UI 树不可见。
- 结论：**无法仅凭 UI 树在用户列表页批量提取候选用户**；只能逐个进入主页读取昵称（tk1）与抖音号（50g），或另需 OCR/截图方案。视频列表则相反，`desc`、作者名 `--`、时间 `3-t`、点赞 `phr` 可在树中读到。
- 该差异是当前“按关键词筛选潜客”的主要技术障碍，不能假设用户列表可像视频列表一样解析。

## 视频与评论- 视频页：作者 `title`、描述 `desc`、评论入口 `e9n`，label 形如“评论1284，按钮”；点赞 `gxu`、收藏 `d_j`、关注 `j_x`、分享 `z0n` 均不得在未确认时操作。
- 本次评论面板标题为 `e7+`、文本“评论 1284”，并非旧模板假设的 `title`；关闭 `back_btn`、放大 `kk0`、列表 `rj=`、评论输入 `e1_`。
- 当前可见评论容器 `fpb` 的 label 包含昵称、评论正文、时间、地区和“回复 按钮”；子项昵称 `title`、正文 `content`、时间 `e8h`、地区 `e4k`、回复 `xs0`、头像 `avatar`；展开回复 `42x`。同 ID 反复出现，必须与父评论容器关联；Mobile MCP 列表投影未提供明确父子关系，应额外验证，不能仅凭顺序或同名做可靠用户关联。
- 本次未发送、点赞、关注或私信；未持久化评论原文、昵称或用户标识。

## 回复与私信入口补采
- 点击展开回复 `42x` 后，出现缩进回复项 `fpb` 和“收起”；顶层及楼中楼复用相同 ID，层级、关联需要额外证明。
- 点击某条评论的 `xs0` 回复进入输入面板：输入框 `e1_`，空内容时发送 `e6k` disabled；树中未明确回读回复目标，不能仅依据昵称或先前点击就自动发送。
- 评论者头像 `avatar` 可进入该用户主页；主页显示昵称 `tk1`、抖音号 `50g`，私信入口 `zma`。本次点击私信入口进入会话，仅观察控件：标题 `vws`、输入框 `msg_et`，未输入或发送；存在陌生人沟通安全提示。未验证不同关系、权限及目标身份唯一性，也未保存用户个人数据。

## 评论区可完整解析（截流主战场，已实测）
- 进入视频后点评论入口 `e9n`；面板含「评论 1284」标签 `e7+`（selected）与「AI 解析」标签（抖音自带汇总评论，未点开验证）。
- 面板顶部有「大家都在搜：」+ 搜索词（`content`），可用于扩展关键词。
- 列表 `rj=`（RecyclerView）；**每条评论容器 `fpb` 的 label 直接含昵称、正文、时间、地区**，形如「毛英阁,[宕机]我有一台三星s10屏幕坏了，能不能帮我弄一套，有偿,10-25, · 内蒙古,回复 按钮,」；子元素 `title`（昵称）/`content`（正文）/`e8h`（时间）/`e4k`（地区）/`xs0`（回复）/`avatar`（头像，label「XX的头像」）/`gw+`（赞，label「赞N,未选中」）/`ddx`（踩）/`42x`（展开N条回复）。
- **上滑评论列表可连续加载新评论并继续解析**（已实测：一次上滑后出现 4 条新评论）。这是“按关键词检索评论、提取潜客”的可行基础。
- 实测样本中出现典型潜客评论：「我有一台三星s10屏幕坏了，能不能帮我弄一套，有偿」——说明该场景真实存在；但样本仅此一条，不能据此估算命中率。
- 风险：`fpb` 仍会重复出现，需按容器与可见区域关联；时间/地区可能因容器过窄被裁（如文字高度仅 13–29px 时内容可能显示不全），文本是否完整需按实际坐标高度判断，不能假定已读全。

## 作者身份与跨机定位（2026-10-31 实测）
- **昵称会重名，不能作为身份**；主页可读 `抖音号：dy465qlkpus8`（元素 `id=50g`），是唯一标识。
- 跨机定位链路已验证：搜抖音号 → 用户标签 → 点第一个用户 → 主页核对抖音号 → 点右上角“搜索” → 输入视频标题 → 命中。
- 主页内搜索提示为“搜索 XXX 发过的作品”，实测“折叠苹果”→ 45 个相关视频、目标在首屏，**不受全局搜索个性化推荐影响**。
- 搜索结果列表的“用户”卡片仍读不到昵称（只有 7 个“关注按钮”），所以必须逐个进主页核对抖音号。
- 旧观察更正（2026-11-01）：搜索卡片的作者入口与播放页作者入口不可混为一谈。实测从搜索封面进入播放页后，点击唯一 `title` 且文本为 `@未来果实` 的作者名，会直接打开作者主页；因此“进主页只能走用户标签”不成立。
- 相对时间会漂移（2小时前→4小时前）、评论数/点赞数会变，**定位只能用“昵称+正文”，不能用时间或位置**。

## 原视频取作者号闭环（2026-11-01 10:19–10:21 实测）
- 前提：确认服务无活动自动任务，仅通过一个 Mobile MCP 操作者浏览1号机，无发送、关注或重启。
- 搜索“手机主板机”→点击封面→播放页，唯一作者 `title` 文本 `@未来果实`，作品 `desc` 文本 `装机太贵，手机来凑#手机数码#装机 `。
- 点击播放页作者名→主页，`tk1=未来果实`，`50g=抖音号：dy465qlkpus8`。
- 单次 BACK→播放页，`e9n/gxu` 在，作者及作品描述与进入前一致。返回树中有屏外残留节点，不能把任意同名文本存在视为当前页面证据。
- 关系依据为“当前视频作者入口直接导航”，昵称仅做一致性检查，不通过昵称搜索确立身份。仅验证一个作者、一个视频；完整标题也不等同全局唯一视频ID。不得据此批量修改历史同名记录。

## 评论发布者取号（2026-11-01 11:54–12:01，2号机实测）
- 用户调整为采集评论人的身份，后续其他账号按身份私信；不再要求重新定位原评论。旧100条试验在74条、16视频停止，不能算完成100条。
- 评论容器 `fpb` 的昵称与完整正文唯一匹配；本例昵称“萌豁”。该容器内 `avatar` 唯一，label恰为“萌豁的头像”，几何范围包含在同一评论容器内。
- 点此头像直接进入主页：`tk1=萌豁`、`50g=抖音号：93812759540`；单次BACK返回评论区，唯一原评论昵称及全文相同。独立helper复验用时6.56秒。
- 此号为评论发布者身份，独立字段 `commenter_douyin_id`；`author_douyin_id` 仍只表示视频来源作者，禁止拿它联系评论人。保留直接导航证据，不昵称搜索补号、不按昵称缓存。
- 本轮不私信、不关注、不发送、不重启。只证实一个评论人的往返路径，未验收跨账号私信定位、主页链接/sec_uid提取或100条规模成功率。

## 中转站（跨平台）
- 每个平台一张独立表：`leads_douyin` / `leads_redbook` / `leads_bilibili`，字段按各自能采到的内容定义，**不混表**。
- 共用的是机制：原子认领（`BEGIN IMMEDIATE`）、租约 600 秒、重试 3 次后放弃、状态机、结果留痕（谁领的、发了什么、成功与否）。
- 加新平台只需在 `PLATFORM_COLUMNS` 里定义一张表 + 写该平台的采集/执行器，中转站其余代码不动。
- 采集结束自动写入抖音表；同一人同一评论同一视频只留一条。
